# Shared Types — AI Assistant Instructions

`@chamuco/shared-types` is the single source of truth for enums and TypeScript types shared across `apps/api` and `apps/web`. Read the root `CLAUDE.md` first.

Changes here affect both packages. See `apps/api/src/database/CLAUDE.md` for the Drizzle side of enum sync.

---

## Structure

```
packages/shared-types/src/
├── enums/
│   ├── index.ts              ← barrel for all enums
│   └── *.enum.ts             ← one file per enum
├── types/
│   ├── index.ts              ← barrel for all types
│   └── *.ts                  ← one file per type/interface
├── data/
│   └── *.ts                  ← static reference data (e.g., loyalty-programs.data.ts)
└── index.ts                  ← root barrel — exports everything
```

---

## Rules

### 1. PG enum sync — required on every enum change

Every TypeScript enum that maps to a PostgreSQL enum must be kept in sync with:

1. The `pgEnum(...)` call in the corresponding `*.schema.ts` file in `apps/api`
2. A migration file generated by `pnpm --filter api db:generate`

Drizzle does **not** auto-read TypeScript enums at generate time — it only sees the array passed to `pgEnum()`. If you add a value to a TS enum, you must also:

- Add the value to the `pgEnum([...])` array in the relevant schema file
- The generated migration will include `ALTER TYPE <pg_type> ADD VALUE '<VALUE>'`

```ts
// shared-types: new value added
export enum VisaType {
  TOURIST = 'TOURIST',
  DIGITAL_NOMAD = 'DIGITAL_NOMAD', // ← added here
}

// apps/api schema file: must match
export const visaTypeEnum = pgEnum('visa_type', [
  VisaType.TOURIST,
  VisaType.DIGITAL_NOMAD, // ← also add here, then run db:generate
]);
```

Never hardcode enum string values in schema files — always import from `@chamuco/shared-types`.

### 2. UploadType — four places must stay in sync

When adding a new `UploadType` value:

1. Add to `UploadType` enum (`src/enums/upload-type.enum.ts`)
2. Add entries to all four `Record<UploadType, ...>` maps in `apps/api/src/modules/cloud-storage/cloud-storage.constants.ts`
3. Add a case to `authorizeUpload` in `apps/api/src/modules/uploads/uploads.controller.ts` (TypeScript exhaustiveness check will fail to compile if omitted)
4. Add the accepted MIME types to `ACCEPTED_TYPES` in `apps/web/src/components/ui/file-upload-button.tsx`

### 3. Barrel exports — always update both levels

All public exports flow through `src/index.ts`. Any new file must be re-exported from:

1. Its sub-barrel (`src/enums/index.ts` or `src/types/index.ts`)
2. The root `src/index.ts`

### 4. No `any`, no runtime logic

This package is types-only (enums + interfaces + static data). Never add business logic, API calls, or side effects. All values must be statically determinable at compile time.
